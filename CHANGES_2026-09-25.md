# magnetocosmics - Change Log (September 25, 2026)

**Date:** September 25, 2026

This document summarizes the changes made to the `magnetocosmics` repository on
September 25, 2026. Three related changes were made: an xBase mis-detection
cleanup, a full Fortran-to-C++ conversion of the magnetic-field models, and a
thread-safety change enabling multithreaded field evaluation.

| Commit | Summary |
|--------|---------|
| `b7817f2` | Remove stray obsolete duplicate misdetected as xBase |
| `1b1e96a` | Convert Fortran magnetic-field models (T89/T96/T01, IGRF) to C++ |
| `e0d5c6b` | Make per-call field COMMON blocks thread-local for safe MT field evaluation |

---

## 1. Remove stray file misdetected as "xBase" (`b7817f2`)

**What changed**

- Deleted `src/desorghe@ubecx.unibe.ch`.

**Why**

- The file was an accidentally-committed, older duplicate of
  `src/MAGCOSMagneticField.cc` (its name is an email address). Its `.ch`
  extension caused GitHub Linguist to classify it as the **xBase** language,
  which showed up as ~5.7% of the repository.
- It was **not compiled** (CMake globs `src/*.cc`) and was not referenced
  anywhere, so removing it is safe and eliminates the bogus language entry.

## 2. Convert the Fortran magnetic-field models to C++ (`1b1e96a`)

The Tsyganenko **T89 / T96 / T01** external-field models and the **IGRF**
internal-field model were originally written in Fortran-77 (`fortran/*.for`,
~27% of the repository). They were translated to C++ so the whole project
builds with a single toolchain and the Fortran language dependency is removed.

**File mapping**

| Original Fortran | C++ translation |
|------------------|-----------------|
| `igrf_to_c++.for` | `igrf_to_cc.cpp` |
| `Tsy89c_mod.for` | `Tsy89c_mod.cpp` |
| `Tsy96_magcos.for` | `Tsy96_magcos.cpp` |
| `Tsyg_01_scaled_to_B0_magcos.for` | `Tsyg_01_scaled_to_B0_magcos.cpp` |

**Supporting files added**

- `*_com.cpp` - one file per Fortran `COMMON` block (its C++ definition).
- `f2c.h` - f2c type definitions, **patched** so `integer` is a 32-bit `int`.
  This makes `COMMON`/argument layout correct on both LP64 (Linux) and
  LLP64 (Windows).
- `f2c_symmap.h` - auto-generated map that renames the translated symbols onto
  the **exact** gfortran-default external names, so the C++ callers
  (`magneto_fsubroutine_def.hh`, etc.) link unchanged.
- `f2c_intrinsics.cc` - the only three f2c runtime helpers actually used
  (`d_sign`, `pow_dd`, `pow_di`). **No external `libf2c` is required.**

**How it was done**

- Mechanical translation with `f2c` (Fortran-77 to C), compiled as C++.
- The translated objects export **exactly the same 86 external symbols** as the
  original gfortran-compiled Fortran, verified with `nm`, so the library is a
  drop-in replacement (`libFortranMagField.a`).
- `fortran/GNUmakefile` now builds `lib/libFortranMagField.a` from the C++
  sources with `g++`; the project's `make` flow is unchanged.

**Numerical verification** (each routine vs. the original gfortran-compiled
Fortran, 300+ randomized inputs):

| Routine | Result |
|---------|--------|
| `t89c`, `t89c_boberg` | **bit-exact** |
| `igrf_to_cc` | matches to ~1e-6 |
| `mcos_t96_01`, `t01_01` | agree to within the models' own finite-difference noise floor; worst case **~0.07 nT**, only at near-zero-field points |

The residual T96/T01 difference was traced (by per-component isolation) to
last-bit differences amplified by the models' internal numerical
differentiation, **not** a translation error: the underlying field components
agree to ~1e-7, and gfortran itself is bit-stable across `-O0`/`-O3`.

## 3. Make per-call field COMMON blocks thread-local (`e0d5c6b`)

To support Geant4 **multithreaded** runs (see the `ECRS2021` repository, which
links this library), the `COMMON` blocks that are written on every field
evaluation were made `thread_local`, so each worker thread has its own private
copy and concurrent field evaluations do not race.

**Made `thread_local`** (written per field call - verified by static analysis):

```
warp_, tail_, rcpar_, dphi_b_rho0__, dtheta_, g_, modenum_, birkpar_,
where_in_magnetopause2001__
```

Applied consistently to each block's definition (`*_com.cpp`) **and** every
`extern` declaration in the model `.cpp` files, plus the exposed block in
`include/magneto_fsubroutine_def.hh`. (A `thread_local`/non-`thread_local`
mismatch across translation units is ill-formed, so all 18 declaration sites
were audited for consistency.)

**Left shared on purpose:**

```
bdip_    (dipole moment)
igrfcc_  (IGRF coefficients)
```

These are set **once** at configuration time and are only **read** during
tracking. Shared read-only access is safe; making them `thread_local` would
have left worker threads with zero coefficients (the field object is
constructed once on the master thread), producing wrong results.

**Verification**

- The library still compiles cleanly; `nm` confirms the scratch blocks became
  thread-local storage while `bdip_`/`igrfcc_` remain ordinary globals.
- **Single-thread results are unchanged by construction** - a `thread_local`
  block with one thread is identical to a zero-initialised global.
- Full Geant4 multithreaded validation (a small `nThreads=1` vs `nThreads>1`
  run, comparing output) should be run on the target build as the final check.
